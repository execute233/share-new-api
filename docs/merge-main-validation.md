本文根据合并提交 `715b0123d` 中的记录翻译整理。合并目标为 main 提交 `2fddb863f`，第一父提交为 share-new-api 的 `6da7152f9`。

合并保留 main 的全部功能和钱包安全保护，同时保留代理池、Shadowsocks 和逐目标质量报告。本文记录的是隔离集成分支的验证结果，不表示当前工作目录已切换到合并版本，也不表示已经部署或修改生产数据库。

## 代理 API 兼容行为

- 创建、更新渠道使用 `proxy_id`。更新时省略该字段会保留现有绑定；显式传入 `null` 表示直连。渠道更新和代理绑定清除在同一事务中完成。
- 模型预览同样区分“省略代理字段”和“显式传入 `null`”。
- 旧的 `setting.proxy` 和模型预览请求中的 `proxy` 不再决定出站连接。运行时渠道设置使用代理池解析出的实际 URL。
- 未绑定代理、代理已删除或停用时使用直连。数据库访问或凭据解密错误会导致操作失败；已选代理连接失败后不会回退为直连。
- HTTP、任务提交与轮询、管理请求、产物获取及 WebSocket 握手均使用解析后的代理。复用 WebSocket 连接时会比较实际代理，因此代理地址或凭据变化后需要重新连接。

## PostgreSQL 预检与升级演练

使用应用的主数据库连接和搜索路径执行配套的 [只读预检 SQL](merge-main-postgres-preflight.sql)。脚本在只读事务中运行，不输出凭据或密钥。仅在部署使用自定义 GORM 命名策略时调整表名。

四个用户额度列都必须报告 `PASS`：

| 结果 | 含义 |
| --- | --- |
| `PASS` | 字段类型为 BIGINT，满足要求 |
| `MIGRATION_REQUIRED` | 字段存在，但需要确认并升级类型 |
| `MISSING` | 字段缺失或表结构不匹配，应排查，不能跳过启动检查 |

本次部署已确认从未创建 CodexDisguise 渠道，因此未包含旧 `type=62` 记录转换；main 的渠道类型 62 为 VLLM。

如果数据库仍有需要扩容的额度列，按以下步骤演练：

1. 使用 `pg_dump --format=custom` 备份整个数据库，并将备份恢复到隔离的演练数据库。使用连接服务文件或现有凭据管理方式，避免将密码写入命令历史。
2. 停止所有向演练数据库写入数据的进程。保存只读预检结果，并将用户额度、订单、订阅、渠道和代理凭据密文的逐行快照保存到受保护的本地位置。
3. 在演练数据库中，仅将仍为 `integer` 的额度列显式扩容。以下为默认表结构的示例；根据预检结果保留需要执行的子句。本次合并任务不执行生产环境 SQL。

   ```sql
   BEGIN;
   SET LOCAL lock_timeout = '5s';
   ALTER TABLE users
     ALTER COLUMN quota TYPE bigint,
     ALTER COLUMN used_quota TYPE bigint,
     ALTER COLUMN aff_quota TYPE bigint,
     ALTER COLUMN aff_history TYPE bigint;
   COMMIT;
   ```

4. 再次运行预检，将合并后的应用连接到隔离数据库并启动，执行正常迁移。不要通过设置 `SKIP_64BIT_QUOTA_SCHEMA_CHECK` 绕过检查。
5. 对比额度及原有记录与快照是否一致。验证登录、兑换码、订单历史、订阅，以及每种已启用代理协议的实际请求。使用相同的 `CRYPTO_SECRET` 配置确认已有加密凭据可以解密，不输出明文。
6. 正式生产升级应另行安排：升级前重新备份并停止写入。如果需要回滚，将旧版本应用与数据库备份一起恢复，不直接将已有数据的 BIGINT 列缩窄。

代理表已接入 main 的统一迁移入口。main 不再包含单独的 `migrateDBFast` 入口。

- 七种语言已同步，包含代理表单校验和动态权限标签；路由文件通过生产构建重新生成。
