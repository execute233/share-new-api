# 出站代理模块规格说明

## 问题陈述（Problem Statement）

当前 new-api 将渠道出站代理保存为渠道 `setting.proxy` 中的自由字符串。管理员需要在多个渠道间重复填写代理 URL，无法集中管理代理凭证、查看代理绑定关系、批量添加代理，也无法在渠道实际转发前了解代理的连通性、延迟、出口 IP、地理位置和 AI 目标质量。

该方式还使 relay、Gemini、Codex、Midjourney、余额查询和上游模型检测等路径分别读取代理字符串，代理策略分散且难以保证一致性。代理凭证也没有独立的掩码和可逆加密存储边界。

## 解决方案（Solution）

新增独立的出站代理资源模块。管理员可以在代理管理页创建、编辑、启停、删除代理，使用 URL 快速添加多个代理，并手动执行连通性和质量检测。代理只保存最近一次检测结果。

渠道通过单个可空 `proxy_id` 选择已有代理，而不是重复保存代理 URL。active 代理可供新绑定；inactive 代理保留已有渠道绑定，但这些渠道运行时直连，代理重新 active 后自动恢复使用。删除代理时清空所有渠道绑定，因此删除后的渠道直连。

relay 和所有渠道相关的上游请求路径统一通过代理解析策略：未绑定或 inactive 代理直连，active 代理使用解密后的代理凭证。旧 `setting.proxy` 保留历史数据但不再被运行时读取。

## 用户故事（User Stories）

1. 作为管理员，我希望查看所有出站代理，以便集中了解代理配置和运行状态。
2. 作为管理员，我希望按名称、协议、状态和关键词筛选代理，以便快速定位目标代理。
3. 作为管理员，我希望创建 HTTP、HTTPS、SOCKS5 或 SOCKS5H 代理，以便为不同上游渠道配置网络出口。
4. 作为管理员，我希望为代理设置名称，以便在渠道选择器中识别代理用途。
5. 作为管理员，我希望为代理配置用户名和密码，以便使用需要认证的代理服务。
6. 作为管理员，我希望代理凭证加密存储且列表只显示掩码，以便降低凭证泄露风险。
7. 作为管理员，我希望编辑代理时密码为空表示不修改，以便不必重新输入已有密码。
8. 作为管理员，我希望显式执行清除认证信息的操作，以便区分“保持原密码”和“删除密码”。
9. 作为管理员，我希望手动启用或停用代理，以便控制代理是否可被新渠道选择。
10. 作为管理员，我希望 inactive 代理不出现在新的渠道选择列表中，以便避免误绑定不可用代理。
11. 作为管理员，我希望已有绑定的 inactive 代理保留绑定关系，以便重新启用后无需重新配置渠道。
12. 作为管理员，我希望 inactive 代理绑定的渠道运行时直连，以便维护代理时不阻塞请求。
13. 作为管理员，我希望删除代理时系统清空关联渠道绑定，以便不留下悬空的 `proxy_id`。
14. 作为管理员，我希望删除确认显示受影响渠道数量，以便了解删除动作的网络路径影响。
15. 作为管理员，我希望按行粘贴代理 URL 快速添加代理，以便批量录入代理池。
16. 作为管理员，我希望快速添加只接受明确协议的 URL，以便避免把 SOCKS5 代理误解析成 HTTP 代理。
17. 作为管理员，我希望快速添加对重复代理返回 skipped，以便重复提交不会产生重复资源。
18. 作为管理员，我希望快速添加返回每一行的错误原因，以便修正无效协议、地址或端口。
19. 作为管理员，我希望错误明细自动脱敏，以便批量操作不会回显代理密码。
20. 作为管理员，我希望手动测试代理连通性和延迟，以便知道代理是否能够建立出站连接。
21. 作为管理员，我希望查看代理出口 IP 和地理位置，以便确认实际网络出口。
22. 作为管理员，我希望执行 AI 目标质量检测，以便发现限流、挑战页面和失败目标。
23. 作为管理员，我希望看到 pass、warn、challenge、fail 分类和质量等级，以便快速判断代理质量。
24. 作为管理员，我希望检测结果只保留最近一次，以便列表保持简洁且不演变为监控历史系统。
25. 作为管理员，我希望质量检测不会自动修改代理状态，以便检测结果和运营启停决策保持分离。
26. 作为管理员，我希望在渠道新增页面选择已有 active 代理，以便不重复填写代理信息。
27. 作为管理员，我希望在渠道编辑页面看到已绑定的 inactive 代理提示，以便理解当前渠道实际直连状态。
28. 作为管理员，我希望在渠道编辑页面选择“无代理”，以便明确切换为直连。
29. 作为管理员，我希望在渠道选择器旁新建代理并自动回填，以便减少页面跳转。
30. 作为管理员，我希望渠道详情只返回安全的代理摘要，以便不会通过渠道 API 泄露代理凭证。
31. 作为管理员，我希望旧渠道的 `setting.proxy` 不再影响 relay，以便代理策略统一由代理资源和 `proxy_id` 控制。
32. 作为管理员，我希望 active 渠道请求确实经过所绑定代理，以便代理配置具有可验证的运行效果。
33. 作为管理员，我希望代理修改、启停、删除和渠道重绑后旧代理 client 缓存失效，以便请求不会继续使用过期配置。
34. 作为系统维护者，我希望支持 SQLite、MySQL 和 PostgreSQL，以便代理模块符合 new-api 的数据库兼容要求。
35. 作为系统维护者，我希望没有稳定加密 secret 时拒绝保存带认证代理，以便重启不会导致凭证无法解密。
36. 作为管理员，我希望代理创建、更新、删除、检测和渠道绑定产生审计信息，以便追踪敏感运营变更。

## 实现决策（Implementation Decisions）

- 代理是独立的出站资源，不与 sub2api 的 Ent 账户/代理模型耦合。
- 新增根项目 GORM `Proxy` 实体，保存名称、协议、host、port、状态、加密认证字段和最近一次测试/质量摘要。
- `Channel` 增加可空 `proxy_id`；未绑定用 `NULL` 表示直连。渠道可以绑定 inactive 代理，但新选择器默认只展示 active 代理。
- 删除代理时在应用事务中先清空关联渠道 `proxy_id`，再删除代理；不依赖数据库特定级联行为。
- inactive 代理运行时直连；质量检测失败不会自动切换或修改代理状态。
- relay 的主解析接缝是渠道选择后的上下文设置过程：初次选路和重试均根据渠道 `proxy_id` 解析代理运行时信息，再由通用 relay request 使用。绕过该接缝的 Gemini、Codex、Midjourney、余额和模型检测路径复用同一代理解析服务。
- 旧 `setting.proxy` 保留历史值但不再由 relay、渠道表单或上游辅助请求读取；没有 `proxy_id` 的旧渠道直连。
- 支持显式 `http`、`https`、`socks5`、`socks5h`、`ss`（shadowsocks）URL；快速添加按协议、host、port、认证组合去重，并返回逐行脱敏结果。`ss` 支持 `ss://method:password@host:port` 明文与 `ss://base64url(method:password)@host:port` 变形，method 白名单为 aes-128-gcm / aes-256-gcm / chacha20-ietf-poly1305（大小写不敏感），端口缺省 8388，目标域名经加密隧道原样发送（远端 DNS）。
- 首期不提供 JSON 导入导出、代理轮询、备用代理、自动熔断、周期检测或检测历史。
- 代理凭证使用 AES-GCM 可逆加密，密钥由显式稳定的 `CRYPTO_SECRET` 或 `SESSION_SECRET` 派生。没有稳定 secret 时，无认证代理仍可创建；带用户名或密码的创建/更新被拒绝。API 永不返回明文凭证或密文。
- 代理列表、详情、渠道详情使用安全 DTO，不直接序列化包含敏感字段的 GORM 模型。
- 质量检测复刻 sub2api 的语义：通过代理查询出口 IP/地理信息并检测默认 AI 目标，记录 pass/warn/challenge/fail，计算质量分数和等级；使用超时、响应大小限制和 SSRF 防护。
- API 使用根项目 `/api/proxy` 风格和 `common.ApiSuccess`/`common.ApiError` 契约，全部受管理员认证和代理资源权限保护；检测属于 operate，普通字段修改属于 write，凭证修改与删除属于 sensitive write。
- 审计仅记录资源 ID、名称、渠道 ID、变更字段和影响数量，不记录 URL、用户名、密码、探测响应或密文。
- 前端新增代理管理功能、管理员路由和侧边栏入口，沿用当前 DataTable、drawer/dialog、React Query、i18next 和权限模式。渠道 drawer 增加 active 代理选择、inactive 已绑定提示、清除绑定和嵌套新建。

## 测试决策（Testing Decisions）

- 主要测试接缝是高层行为：通过 Gin 管理 API、渠道更新 API 和 relay 测试入口观察 JSON 响应、数据库可见状态和实际 HTTP transport 行为。
- 仅为隔离外部 IP/AI 探测注入高层 `ProxyProbe`/`ProxyTester` 接口，不 mock 私有 helper 或绑定实现细节。
- URL 解析测试覆盖允许协议、非法协议、host/端口、认证、路径/query/fragment、IPv4/IPv6、规范化和重复键。
- 加密测试覆盖稳定 secret 循环解密、长凭证、错误密文、缺少稳定 secret 和 API 掩码；测试断言不出现明文凭证。
- API 测试覆盖 CRUD、分页筛选、快速添加部分成功、逐行错误脱敏、active 选择过滤、权限拒绝、审计字段和删除绑定事务。
- relay/transport 测试通过 httptest 上游和代理观察 active 代理使用、inactive 直连、未绑定直连、缓存失效和旧 `setting.proxy` 不生效。
- 质量检测测试覆盖最近结果替换、pass/warn/challenge/fail 分类、分数等级、超时和安全降级，并断言检测不改变代理状态。
- 渠道测试覆盖创建绑定 active/inactive、更新绑定、显式清除和返回安全代理摘要。
- 数据库测试使用 SQLite 行为 fixture，并审查/验证 GORM 生成的 SQLite、MySQL、PostgreSQL 兼容迁移和事务查询。
- Go 测试使用 `require` 进行 setup/fatal 断言、`assert` 进行非 fatal 断言；前端测试使用现有 Vitest/React Query/i18n 接缝，不测试布局内部实现细节。

## 范围之外（Out of Scope）

- 入站客户端 IP、IP 白名单/黑名单、可信转发头和来源 IP 审计。
- 多代理轮询、随机选择、备用代理链、自动回退、自动熔断和周期调度。
- 真实 IP 欺诈、黑名单、VPN/Tor/匿名性信誉供应商和供应商 API Key 管理。
- 质量检测历史、趋势、告警和统计图表。
- JSON 导入导出及加密凭证备份恢复。
- 旧 `setting.proxy` 自动迁移、自动提示或解析。
- 质量检测自动停用代理或自动改变渠道状态。

## 进一步说明（Further Notes）

- 删除代理会导致绑定渠道转为直连，这是显式资源删除行为；inactive 则是可逆的运行时直连状态，重新 active 后恢复代理。
- 稳定 secret 的判断必须基于显式环境配置，而不能只判断当前进程内 `common.CryptoSecret` 是否非空，因为项目默认值可能是启动时随机 UUID。
- 新代理模块中的加密文本字段必须使用足够大的跨数据库文本类型，避免 AES-GCM 密文截断。
- 实现完成后，必须全仓搜索运行时旧代理读取（例如 `GetSetting().Proxy`、`ChannelSetting.Proxy`、`setting.proxy`），任何遗漏都视为发布阻塞项。
